# Security Policy

## Supported versions

| Version or branch | Security support |
| --- | --- |
| Latest stable release | Receives security fixes |
| `main` | Receives fixes during active development |
| Older releases | Unsupported. Upgrade to the latest stable release. |

## Reporting a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/WeighInNG/WeighIn/security/advisories/new)
when it is available. If the form is unavailable, contact a project maintainer
privately using the contact information on their GitHub profile, as described
in the [Code of Conduct](CODE_OF_CONDUCT.md). Keep vulnerability details out of
public issues, pull requests, and discussions.

Include the affected version or commit, the component involved, the impact, and
enough information for maintainers to confirm the issue. Redact credentials and
personal data from any logs or attachments.

## Response and disclosure

Maintainers aim to acknowledge reports within seven calendar days. They will
triage the report, share status updates through the original private channel,
and coordinate a fix and disclosure with the reporter. Fix timing depends on
severity and complexity. Confirmed vulnerabilities will be documented in a
security advisory when a fix or mitigation is available.
